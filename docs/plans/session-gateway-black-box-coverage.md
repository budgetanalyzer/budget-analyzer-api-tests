# Session Gateway Black-Box Coverage Plan

Extend this repository from partial Session Gateway smoke coverage to an explicit, executable
inventory of every inbound Session Gateway HTTP surface. Exercise every deterministic behavior
available through the deployed browser-facing HTTPS origin, preserve the separately generated
Session Gateway OpenAPI contract as a reviewed snapshot, and report every inaccessible or
non-deterministic behavior with an exact reason and prerequisite instead of implying coverage.

The current inbound surface is:

- public ingress: `GET /oauth2/authorization/idp`, `GET /login/oauth2/code/idp`,
  `GET /logout`, `GET /auth/v1/user`, and `GET /auth/v1/session`;
- mesh-internal: `DELETE /internal/v1/sessions/users/{userId}`;
- deployment-operational or development-only: Actuator health/metrics and the service-local
  Springdoc/Swagger routes.

The filtered Session Gateway OpenAPI document currently describes `logout`, `getCurrentUser`, and
`getSessionStatus`; Spring Security owns the authorization and callback routes, and the generator
filters the internal revocation route. The plan must therefore use both OpenAPI operation coverage
and an explicit non-OpenAPI route/case inventory. The corrected OpenAPI document declares the
externally observable `302 Found` response for `logout`, including the identity-provider logout URL
in the `Location` header. Treat that declaration as the executable contract and retain semantic
assertions for the redirect target.

All live requests must continue through the selected environment's public HTTPS origin and the
shared `GatewayClient`/browser pacer. Do not add Kubernetes, service-DNS, Redis, database, forged
workload identity, direct identity-provider token exchange, TLS bypass, or fault-injection paths.
Production remains read-only. OAuth and logout tests may create only a test-owned session for an
existing configured test identity and must invalidate that session in the same scenario. The plan
does not authorize changes to sibling repositories. Mesh-internal endpoints remain inventoried but
untestable by design in this harness: no pod-specific or workload-identity test lane is planned.

## Phase 1: Establish the Session Gateway contract and coverage inventory

### Workspace

.

### Goal

Make Session Gateway a first-class, namespaced contract in the offline coverage model and establish
one exhaustive inventory that distinguishes public test cases from inaccessible or
environment-dependent cases.

### Scope

Add a reviewed Session Gateway OpenAPI snapshot, typed contract identity, namespaced pytest marker
support, an inbound-route/case inventory, deterministic coverage validation, artifacts, unit tests,
and the documentation needed to refresh and review the contract.

### Non-goals

Do not issue live requests, modify Session Gateway annotations, expose a new docs route, change
orchestration routing, or mark an endpoint covered merely because service-local integration tests
exist.

### Required context

Read `AGENTS.md`, `README.md`, `docs/openapi-coverage.md`, `src/api_tests/openapi.py`,
`src/api_tests/coverage.py`, `src/api_tests/pytest_plugin.py`,
`src/api_tests/tools/openapi_coverage.py`, and the OpenAPI unit tests. Read
`../orchestration/scripts/repo/generate-unified-api-docs.sh`,
`../budget-analyzer-web/docs/api/session-gateway-api.yaml`, `../session-gateway/AGENTS.md`, the four
Session Gateway controllers, `SecurityConfig.java`, `application.yml`, and the orchestration auth
route and Session Gateway authorization policy. Before editing `AGENTS.md`, read
`../orchestration/docs/agents-md-checkstyle.md` completely.

### Execution steps

1. Add a checked-in Session Gateway OpenAPI snapshot under `schemas/`, preserving the filtered
   artifact generated by orchestration. Record its source and the exact explicit-output refresh
   command; the test harness must never invoke `kubectl` or read a live service directly.
2. Generalize OpenAPI loading and coverage records so each operation belongs to a stable contract
   key. Preserve existing one-argument `@pytest.mark.openapi("operationId")` markers as the unified
   API default and support an explicit Session Gateway contract qualifier without allowing
   operation-id collisions to merge coverage.
3. Add a declarative Session Gateway inbound-route and scenario inventory. For every public,
   internal, operational, and development-only route, record method, path, owning mechanism
   (controller, Spring Security, Actuator, or Springdoc), exposure, expected behavior cases,
   testability, and—when deferred—one exact reason plus the prerequisite that would make it
   executable.
4. Classify direct internal revocation, non-public Actuator, and service-local Springdoc/Swagger
   routes as untestable by this harness's architectural boundary. Initially defer heartbeat
   account-deactivated/missing, dependency timeout/unavailability/invalid payload, Redis failure,
   and refresh race; natural TTL expiry; logout Redis deletion failure; and OAuth callback IdP,
   permission-service, and Redis failure branches. Do not classify successful public OAuth, user,
   heartbeat, or logout behavior as deferred.
5. Extend the coverage checker and stable JSON artifact so an OpenAPI operation or inventory case
   is exactly one of covered, deferred, or untestable by architectural boundary. Fail on unknown
   markers, duplicate case ids, missing reasons, missing prerequisites for deferred work, stale
   OpenAPI method/path/operation ids, and inventory entries that conflict with the Session Gateway
   snapshot. Untestable entries must name the enforced boundary and must not masquerade as planned
   work.
6. Validate that the Session Gateway snapshot preserves the corrected `logout` `302` response and
   URI-formatted `Location` header. Reject a stale `200` declaration through the normal snapshot
   review and contract-drift workflow rather than carrying special-case reporting.
7. Add deterministic unit tests for YAML/JSON snapshot loading, contract-qualified markers,
   collision handling, complete inventory accounting, stale entries, coverage artifacts, and
   useful validation errors.
8. Update `README.md`, `docs/openapi-coverage.md`, pytest marker declarations, and `AGENTS.md` so the
   repository purpose says that all system API surfaces are inventoried while supported live tests
   still use authorized black-box lanes. Retain the prohibition on direct internal infrastructure
   access and explain that inaccessible operations must be reported, not ignored.

### Implementation notes

The Session Gateway snapshot is review input, not a runtime sibling-repository dependency. Prefer a
contract keyword on the existing marker, such as
`@pytest.mark.openapi("getCurrentUser", contract="session_gateway")`, and validate the grammar
strictly. Give non-OpenAPI cases stable ids independent of Java or Spring class names so a framework
replacement can satisfy the same observable contract. Keep the existing unified API artifact
consumable; either add an explicit `contract` field compatibly or write a separate stable Session
Gateway coverage artifact.

The route inventory must not treat an external request to `/internal/...` as an internal endpoint
test: the public catch-all route can answer without the request ever reaching Session Gateway. It
must also distinguish an operation-level marker from response/behavior-case coverage.

### Validation

Run:

```bash

.venv/bin/python tools/check-openapi-coverage.py --env local
.venv/bin/python -m pytest tests/api --env local --collect-only
.venv/bin/python -m ruff format --check .
.venv/bin/python -m ruff check .

```

Inspect the generated coverage JSON and verify that it contains no credentials, cookies,
authorization headers, IDP state, or authorization codes.

### Completion criteria

The separate Session Gateway snapshot and complete inbound-route inventory are checked in; every
known route and behavior case is deterministically covered, deferred with a prerequisite, or
untestable by an explicit architectural boundary; the three generated Session Gateway OpenAPI
operations cannot be confused with unified API operations; the corrected logout redirect contract
is preserved in the snapshot; and all focused offline validations pass.

## Phase 2: Cover the user and heartbeat machine APIs

### Workspace

.

### Goal

Provide schema-backed and semantic black-box coverage for every deterministic `GET /auth/v1/user`
and `GET /auth/v1/session` behavior available from normal public clients.

### Scope

Test missing, invalid, and valid sessions through public ingress; validate the Session Gateway
OpenAPI response schemas where the snapshot defines them; verify cookie behavior and heartbeat
semantics; and connect each test to exact Session Gateway operation and case ids.

### Non-goals

Do not manipulate Redis, alter account status, stop permission-service, wait for the configured
session TTL, or infer that unavailable failure branches passed.

### Required context

Read the Phase 1 snapshot, inventory, marker rules, and coverage artifact; `tests/conftest.py`,
`tests/api/auth/test_edge_auth.py`, `tests/api/auth/test_auth_smoke.py`, `src/api_tests/client.py`,
`src/api_tests/schemas.py`, `src/api_tests/session.py`, and request-log redaction. Re-read the
Session Gateway user/session controllers, response records, cookie helper contract, and
`docs/session-configuration.md` in `../session-gateway`.

### Execution steps

1. Create a dedicated `tests/api/session_gateway/` area and move or refactor the existing manual
   user/session checks without losing their production-safe unauthenticated coverage.
2. For `getCurrentUser`, test a missing cookie and a syntactically plausible invalid opaque cookie,
   requiring `401`, JSON, the Session Gateway `ApiErrorResponse` schema, `UNAUTHORIZED`, and the
   stable public message. Test a valid primary session with the `UserInfoResponse` schema and
   semantic assertions for `authenticated`, non-empty identity fields, and typed role/permission
   collections without embedding environment-specific grants.
3. Keep the independently acquired secondary-user smoke, but make operation and case accounting
   explicit and avoid claiming that duplicate successful identities add a new response contract.
4. For `getSessionStatus`, test missing and invalid cookies. Require the documented `401` JSON
   schema; for an invalid non-empty cookie also require the public session cookie to be expired or
   cleared without recording its value.
5. Call heartbeat with a valid primary test session and require `200`, the
   `SessionStatusResponse` schema, a non-empty user id, typed roles, and a future UTC epoch expiry.
   Follow it with `GET /auth/v1/user` and require a still-valid session and roles consistent with
   the heartbeat response. Do not assert exact TTL timing beyond a bounded, clock-tolerant future
   value.
6. Mark authenticated heartbeat as `mutation` because it refreshes grants and expiry even though it
   uses GET. Keep missing/invalid-session reads production-safe only when they cannot refresh state;
   keep the authenticated user read `readonly` and `production_safe`.
7. Add an unknown `/auth/v1/...` route assertion and supported-route wrong-method assertions where
   the public contract has a stable non-HTML 404/405 behavior. Account for these as gateway-routing
   regressions, not OpenAPI operations.
8. Add unit tests for any new response or cookie assertion helpers and update nearby documentation
   with the exact behavior now covered and the failure branches still deferred.

### Implementation notes

Use `GatewayClient.raw_request` because Session Gateway routes are not under `api_base_path`.
Construct invalid sessions in memory and never write their opaque values. Schema assertions must
select the Session Gateway snapshot explicitly. Tests must remain order-independent and must not
invalidate the session-scoped primary or secondary fixtures.

### Validation

Run:

```bash
.venv/bin/python -m pytest tests/unit --env local
.venv/bin/python -m pytest tests/api/session_gateway --env local --collect-only
./run-tests tests/api/session_gateway -k 'user or session'
.venv/bin/python tools/check-openapi-coverage.py --env local
.venv/bin/python -m pytest tests/api --env production -m "readonly and production_safe" --collect-only
.venv/bin/python -m ruff format --check .
.venv/bin/python -m ruff check .
.venv/bin/python -m mypy src tests
```

Treat the selected `./run-tests` invocation as partial validation.

### Completion criteria

Both machine endpoints have negative and successful public-ingress coverage with schema and
semantic assertions; heartbeat mutation safety is accurate; invalid-cookie clearing is verified;
the shared sessions remain usable; exact operation/case coverage is reported; and focused live and
offline checks pass.

## Phase 3: Cover OAuth authorization, callback, cookie, and logout lifecycle

### Workspace

.

### Goal

Exercise the complete browser-visible Session Gateway lifecycle across Spring Security-owned
routes and prove that a test-owned session is created, usable, and actually revoked by logout.

### Scope

Add public no-follow redirect checks, observable browser-flow assertions, safe and rejected return
URL cases, cookie-contract checks, isolated session acquisition, logout redirect/clearing, and
post-logout invalidation.

### Non-goals

Do not exchange tokens directly, inspect Auth0 tokens, follow logout into the hosted provider,
change provider configuration, revoke the reusable account, rely on browser history alone as API
proof, or leave an extra live session behind intentionally.

### Required context

Read the Phase 1 route/case inventory, `src/api_tests/browser_login.py`, `src/api_tests/auth.py`,
local credential handling, browser/auth unit tests, environment auth modes, and request pacing.
Read the Session Gateway security configuration, authorization-request repository, callback
redirect resolver and handlers, redirect validator, session cookie helper, logout controller, and
the durable return-URL/cookie behavior in Session Gateway documentation.

### Execution steps

1. Add typed browser-flow observations that can prove the same-origin authorization entry and
   callback routes were traversed without capturing authorization codes, state values, session
   cookies, passwords, or provider tokens in failures or artifacts.
2. Test `GET /oauth2/authorization/idp` without following redirects. Require an OAuth authorization
   redirect with the configured HTTPS callback path, authorization-code flow, non-empty state,
   OIDC scope, and PKCE parameters where those are part of the durable contract. Compare hosts and
   parameter presence; do not snapshot environment-specific client ids or provider query ordering.
3. Extend browser login only as needed to accept an expected same-origin return path and to report
   whether `/login/oauth2/code/idp` was observed. Keep every same-origin browser request on the
   shared pacer.
4. Add an isolated lifecycle fixture for browser-preprovisioned local/staging environments. It may
   log in the existing configured test identity to create one additional opaque session, but it
   must not replace or invalidate the session-scoped primary fixture and must expose no credentials
   in reprs or diagnostics. In supplied-session mode, skip only scenarios that genuinely require a
   newly owned session and state the missing prerequisite.
5. Exercise successful default and explicit safe-return-URL flows. Require callback traversal, the
   final same-origin path, a `BA_SESSION` cookie with the configured name plus HttpOnly, Secure, and
   expected SameSite attributes, and a successful schema-backed user read. Assert that no framework
   `SESSION` cookie becomes part of the public contract.
6. Exercise representative malicious return URLs—external absolute and protocol-relative values—
   through the complete flow and require the documented safe same-origin fallback. Avoid a matrix
   that creates unnecessary hosted-provider sessions.
7. For each isolated session, call `GET /logout` without following the external redirect. Require
   the OpenAPI-declared `302` and URI-formatted `Location` header, the allowlisted provider logout
   endpoint, an encoded configured return target, and clearing of the public cookie. Do not record
   the full redirect URL when it contains environment identifiers.
8. Reuse the pre-logout opaque cookie in fresh clients and require both user and heartbeat to return
   `401`; this proves server-side invalidation rather than only browser cookie deletion. Also test
   logout without a cookie as an idempotent redirect/clear operation.
9. Mark OAuth entry/success as mutation because state/session data is created and logout as
   destructive. Keep these tests out of production defaults. Ensure cleanup is explicit in each
   lifecycle scenario rather than a generic janitor callback.
10. Add only deterministic callback-negative cases whose expected redirect is documented and whose
    execution does not make uncontrolled provider calls. Leave transport, token exchange,
    permission synchronization, and Redis callback failures deferred with their exact
    prerequisites.
11. Add unit tests for URL validation, observation redaction, lifecycle fixture policy, cookie
    assertions, and no-follow redirect parsing. Update coverage and operational documentation.

### Implementation notes

Logout's OpenAPI response now describes the durable browser redirect contract. Validate the
declared `302` and `Location` header as well as the redirect's provider-specific semantics. The test
must stop at the first provider logout redirect. A `finally` block may attempt narrowly scoped
logout of the exact test-owned session after an assertion failure, but it must not become a generic
cleanup registry and must not hide the original failure.

Browser event diagnostics should retain only method, same-origin path, response status, and a
redacted external host classification. Verify redaction with unit tests before enabling artifacts.

```bash
.venv/bin/python -m pytest tests/api/session_gateway --env local --collect-only
./run-tests tests/api/session_gateway -k 'oauth or callback or logout'
.venv/bin/python tools/check-openapi-coverage.py --env local
.venv/bin/python -m ruff format --check .
.venv/bin/python -m ruff check .
.venv/bin/python -m mypy src tests
```

Inspect the isolated run's request log and failure diagnostics for secrets. Treat the selected
`./run-tests` invocation as partial validation.

### Completion criteria

The authorization entry, successful callback, safe return handling, public cookie contract,
authenticated logout, unauthenticated logout, and server-side post-logout invalidation are proven
through public ingress; each created session is narrowly cleaned up; sensitive OAuth/session data
is absent from artifacts; and deterministic callback failure cases are either tested or explicitly
deferred.

## Phase 4: Make untestable and fault-dependent coverage honest and actionable

### Workspace

.

### Goal

Finalize exact, reviewable accounting for Session Gateway behaviors that the public black-box lane
cannot currently execute, including the internal revocation API.

### Scope

Validate exposure and prerequisite classifications, add stable reporting and policy tests, document
the optional indirect public proof, and ensure no untestable behavior is represented by a
placeholder test or an unrelated external request.

### Non-goals

Do not add an admin identity, deactivate a real reusable test account, expose `/internal`, mint a
SPIFFE identity, call Kubernetes services, introduce fault injection, or weaken mesh authorization.

### Required context

Read the completed Session Gateway inventory and coverage artifacts; the orchestration auth
`HTTPRoute`; local and production Session Gateway `AuthorizationPolicy`; permission-service user
deactivation contract and its Session Gateway client; existing admin deferral manifests; production
safety rules; and the repository's authorization/data-isolation documentation.

### Execution steps

1. Confirm that `DELETE /internal/v1/sessions/users/{userId}` is absent from public ingress and is
   admitted by mesh policy only for permission-service. Classify direct execution as untestable by
   this harness because both routing and workload identity are intentionally absent—not because the
   endpoint is low priority or temporarily unfinished.
2. Document the preferred future public black-box proof: provision a disposable target identity
   with an active session, use a separately approved admin identity to call the public
   permission-service deactivation operation, and require the target's user and heartbeat requests
   to become `401`. State that this proves the end-to-end revocation workflow but does not isolate
   the internal hop.
3. State explicitly that pod-specific requests, a forged or delegated permission-service identity,
   and a trusted service-to-service runner are outside this repository's planned execution model.
   A future explicit charter change could revisit that decision, but the coverage report must not
   present a direct internal test lane as expected follow-up work.
4. Require the internal-revocation entry to retain its untestable classification even if indirect
   admin deactivation coverage is later added. Track the missing admin/disposable-user safety model
   only as the prerequisite for that optional end-to-end scenario. Keep the existing admin/global
   operation deferral unchanged.
5. Review every fault- and time-dependent deferred case. Merge duplicates, retain exact observable
   outcomes, and name the narrow prerequisite: approved dependency fault injection, controllable
   test deployment, disposable deactivated user, configurable short-lived test session, or
   publicly exposed operational route. Do not use generic reasons such as “hard to test.”
6. Add deterministic tests that coverage reports cannot claim full Session Gateway behavior while
   any deferred or untestable cases remain. Report operation coverage and scenario coverage
   separately and print both classifications, counts, and ids in CLI output and JSON.
7. Update `README.md`, `docs/openapi-coverage.md`, and `AGENTS.md` with the final coverage matrix,
   refresh procedure, public-versus-internal distinction, current limitations, and the exact
   prerequisites for closing each gap.

### Implementation notes

An external request to `/internal/v1/sessions/users/...` may be useful as an ingress-hardening test,
but it must have its own route-security case id and must never satisfy the internal operation's
behavior coverage. Likewise, the existing permission-service controller's local integration tests
are context only and do not count as deployed Session Gateway evidence.

Keep status wording precise: “all known inbound routes inventoried,” “all currently executable
public cases covered,” “N cases deferred,” and “N cases untestable by the current boundary” are
valid; “full Session Gateway coverage” is not valid while any case remains deferred or untestable.

## Phase 5: Integrate the full local regression and documentation

### Workspace

### Goal

Prove that Session Gateway coverage participates in the normal repository workflow and that the
complete suite remains safe, deterministic, typed, documented, and secret-free.

### Scope

Run the complete quality and live regression gates, resolve integration defects in this repository,
inspect artifacts, and ensure normal output states covered and deferred Session Gateway behavior
accurately.

### Non-goals

Do not refresh accepted snapshots merely to make drift pass, broaden production permissions, fix
sibling service defects, or convert missing prerequisites into harness workarounds.

### Required context

Read all prior phase outputs, `run-tests`, `src/api_tests/local_runner.py`, environment validation,
artifact documentation, CI workflows, and the full quality-gate list in `AGENTS.md`. Confirm local

### Execution steps

1. Integrate Session Gateway contract and case validation into the no-selector `./run-tests`
   preflight. Keep selector runs explicitly partial and avoid fetching any non-public service-local
   OpenAPI route at runtime.
2. Ensure full-run summary output reports unified API operation coverage, Session Gateway OpenAPI
   operation coverage, Session Gateway behavioral case coverage, contract drift, and exact deferred
   and untestable counts without claiming inaccessible cases passed.
3. Run the full local suite twice when browser credentials are available: once to cover normal
   execution and once to prove reusable identities, independent sessions, and lifecycle cleanup do
   not create ordering or state leakage.
4. Inspect per-run request logs, coverage/drift JSON, pytest/JUnit output, and browser diagnostics.
   Verify that passwords, emails, session cookies, state, authorization codes, redirect query
   secrets, and authorization headers are absent.

7. Reconcile `README.md`, `docs/openapi-coverage.md`, environment examples, marker documentation,
